--- Matthew Flatt <mflatt@cs.utah.edu> wrote:
> How about a "srfi" collection where each SRFI has
> it's own numerically
> named sub-collection? 

The only problem I can see with this is that the
numbers don't say much about the intended function of
the library.  No doubt this won't be a problem for the
gurus, who will translate numbers to names in their
heads, but it makes the code more opaque to less
experienced hackers.

Some SRFIs specify a name for the library.  For
example, to quote from SRFI-1:

"In a Scheme system that has a module or package
system, these procedures should be contained in a
module named "list-lib". "

Other SRFIs could have a sub-collection name based on
their title.
