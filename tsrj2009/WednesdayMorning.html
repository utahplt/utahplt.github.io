2.3.1 Wednesday Morning Exercises

Wednesday Morning Lecture

  1. Get set up with vfamily-count and vfamily-find from lecture.

  2. Write vfamily-move, which takes a vfamily and an iworld and produces a vfamily where all animals have moved to the given iworld.

    Remember that you can use iworld1, iworld2, and iworld3 to test your function.

  3. Write vfamily-reunion, which takes a vfamily and a string, and produces a vfamily where all descendants of the animal with the given name move to that animal’s current home.

    This function offers an interesting case of reuse, where you start by writing vfamily-reunion but discover that vfamily-move is useful in one sub-case of the function.

  4. Write vfamily-add, which takes a vfamily, a name string, a kind string, and a place iworld, and returns a vfamily that adds a new animal to the family.

    For an empty family, just add the animal as a new parent. For a family that is a parent, add the new animal as an descendant of child1 if child1 currently has fewer animals than child2, otherwise add the new animal to child2’s tree.

  5. Optional: A server sends a message back to a world using a mail value. A mail value is created by make-mail, which takes an iworld and a string message.

    Write vfamily-move-mails, which takes a vfamily and an iworld and produces a list-of-mails. For each animal that is not currently at the given iworld, include two mails in the list: one to the animal’s current location with a "gone" message, and one to the given world with a "cat" or "cham" messages.

    You’ll need the append function to combine lists.

  6. Optional: To actually send a list-of-mails, a server function combines the list-of-mails with the new vfamily (plus a list-of-iworlds to disconnect from, for which we’ll use empty) in a bundle created with make-bundle.

    Write vfamily-reunion-msg, which takes a vfamily and a string to name an animal. It should return a bundle that has the family after moving all the known descendants of the named animal, and it should have a list-of-mails that move all the descendants that need to move for the reunion. You can assume that and animal with the given string name exists in the given vfamily.

    Now is a good time to think about the pieces that you already have: vfamily-reunion, vfamily-find, and vfamily-add.

  7. Optional: To put our pieces together into an animal-universe server, we’ll still need a few more parts. We will create a server with

      (universe empty
                (on-new vfamily-new)
                (on-msg vfamily-msg))

    and we still need to write vfamily-new and vfamily-msg.

    1. The vfamily-new function consumes the current vfamily and an iworld. It produces a bundle with the new world, a list-of-mails, and an empty list-of-iworlds.

      To add a new animal to the current family, use vfamily-add with a new name, "cat" or "cham", and the iworld supplied to vfamily-new. You can make a new name by counting how many animals are already in the family:

      (string-append "Sal" (number->string (vfamily-count vfam)))

      Similarly, you could pick "cat" versus "cham" based on whether there are currently an even or odd number of animals in the family. Or you could just always use "cat".

      The list-of-mails in the bundle should send a "cat" or "cham" message back to the newly added iworld (i.e., the one supplied to vfamily-new).

    2. The vfamily-msg function consumes the current family, an iworld that we can ignore, and a string for the message from a world. The only message that we handle is one starting with "reunion" followed by a space and an animal name. The result is a bundle, which can be produced by vfamily-reunion-msg.

    3. Put the pieces together. Use your virtual-animal world from yesterday and connect to your server by using LOCALHOST instead of "rains.cs.utah.edu".
